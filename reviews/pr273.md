## 必须修复

### P2：尺寸规则没有完整区分生成场景，仍会发送官方不支持的 size

位置：`backend/internal/providerpreset/seedream.go:113`，以及 `seedream.go:131`。[固定提交源码](https://github.com/glanderness/BeefTV/blob/fa47a153c92ccf41853c9829069d1d475d322c6f/backend/internal/providerpreset/seedream.go#L113)

`ResolveSeedreamSize` 仅在处理画布比例时检查 `layers`。随后无条件接受 `auto`，解析显式像素尺寸时也不再检查生成场景。因此：

- 普通生图会把 `auto` 原样发出。官方普通生图规则列出的方式是分辨率档位或宽×高，`auto` 是 Pro/Flash 图层拆分的专用选项。
- 图层拆分会把 `2048x2048` 等显式像素尺寸原样发出。官方该场景只接受 `1K`、`1.5K`、`2K`、`auto`。

依据：[火山方舟图片生成 API 的 size 说明](https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh)。这两种场景不能仅共用普通生图的总像素校验。

离线复现从 `RunImageTask` 进入，加载仓库真实 Ark manifest，以 `captureImagePort` 拦截请求并返回合成 PNG。Base URL 为官方 Ark 地址，凭据与图片均为合成测试值，没有访问供应商：

| 输入 | 主线基线拦截结果 | PR 拦截结果 | 判断 |
| --- | --- | --- | --- |
| 国内 Pro，普通生图，`size=auto` | `size=2k` | `size=auto` | 本次改变了实际发送值，不符合普通生图规则 |
| 国内 Flash，普通生图，`size=auto` | `size=2k` | `size=auto` | 同上 |
| 国际 Pro，图层拆分，`size=2048x2048`，一张参考图 | `layer_decomposition=true`、`size=2048x2048` | 同左 | 原有遗漏仍未补齐 |
| 国内 Pro，图层拆分，`size=2048x2048`，一张参考图 | 国内型号尚未进入专用请求体 | `layer_decomposition=true`、`size=2048x2048` | 新支持的国内图层功能也会发送无效尺寸 |
| 国内 Pro，图层拆分，`size=auto`，一张参考图 | 国内型号尚未进入专用请求体 | `layer_decomposition=true`、`size=auto` | 正向对照：此场景应继续接受 auto |

PR 中上述调用都没有报错，均到达一次模拟 POST，路径为 `/api/v3/images/generations`。另外通过现有 fixture 调用普通生图的 configure、prepare、propose，三者也全部接受 `auto`；configure 实际写入草稿，prepare 实际进入分镜准备。

这不是已经证实的供应商扣费事故：未向真实上游请求，也未验证上游如何收费。已证实的是，本地预检和最终请求都会放过与官方合同不符的组合；普通生图的国内型号还失去了主线已有的档位映射。

最小修复方向：继续共用现有解析函数，补齐场景判断。普通生图的 `auto` 建议解析为默认 `2K`，延续主线的处理意图；图层拆分保留合法 `auto`，拒绝显式像素尺寸并提示改选档位。预检应取节点现有配置与 patch 合并后的 `seedreamMode`，否则只改 size 时无法判断节点是否正在拆图层。补充实际请求断言；当前 `backend/internal/providerpreset/seedream_test.go:54` 反而把普通生图返回原样 `auto` 固定成了正确结果。
