# v2.0.6 验收计划

这份计划交给执行验收的 Agent。v2.0.6 是一次大重构后的版本：自 v2.0.5 起合入 32 个 PR，生成链路、取回逻辑、模型协议和画布页面都改过。验收要回答两个问题：

1. 这一版声称修好的问题，在真实客户端里是不是真的好了；
2. 用户平常会走的流程，重构之后是不是都还正常。

本版不豁免标准验收：[每次桌面发版的真实生成验收](../real-generation-release.md) 里的十二条真实生成和助手专项照常执行。

## 0. 执行规则

必须做：

- 开工前向发布人（Claude）确认候选提交。候选必须已经把 `VERSION` 改成 `v2.0.6`，并且已经写好更新说明。候选冻结后，验收期间不换代码；如果中途合入了修复，受影响的条目要在新候选上重做。
- 每一条都写清实际看到了什么：截图、录屏、任务 ID、文件 SHA256、日志片段。没亲眼看到的不写「通过」，写 `not_run` 并说明原因。
- 每次付费提交前，先在客户端看当前报价，按第 6 节核对预算；提交后立刻记下本地任务 ID。
- 付费任务失败、超时或结果不确定时，先查询原任务、点「继续取回」，不要重新提交。确需再付费一次的，先问 Ender。
- 发现问题就停下这一条，按第 7 节记录，接着做其他条目。不要自己改代码。
- 记录里不写 API Key、Cookie、签名下载链接和客户素材。

禁止做：

- 不在 `mem`（/home/user/workspace/BeefTV）或其他会话正在用的工作区执行 `git reset`、`git checkout`、`git pull` 等改动操作。
- 不合并 PR，不触发发布流程，不改 BeefAPI 线上配置。托管音频、托管超分开关（`MANAGED_AUDIO_TASKS_ENABLED`、`MANAGED_UPSCALE_TASKS_ENABLED`）保持关闭。
- 不把 CI 通过、浏览器测试通过或直接调接口成功，当成真实客户端验收通过。

## 4. 第三部分：标准真实生成矩阵和助手验收

按 [每次桌面发版的真实生成验收](../real-generation-release.md) 执行，不豁免：

- 6 条路径 × 2 轮，共 12 次真实生成，全部由内置助手发起：助手提出方案，你在客户端点方案卡片上的「生成」。路径和模型按该文档的表格：文生图、图生图用 Image 2.5（`gpt-image-2.5`）最低画质；图生视频、文生视频、视频生视频、多素材生视频用 Seedance 2.0 Fast（`seedance-2.0-fast`）、480p、16:9、5 秒。两轮用同一套 P8 冻结的素材和提示词。
- 每条都要核对：任务追到完成 → 客户端下载 → 结果落到画布 → 打开图片或播放视频 → 最终结算。
- A2、A3、A12、B6 安排在这 12 次里做，不另外花钱。中断要避开第二轮的同一路径，保证两轮里至少一轮是不中断的正常完成。
- 助手专项：该文档「Agent 联合验收」里的 15 项 `agentChecks` 和 8 项新增专项，逐项按要求的方式（native 或允许的 deterministic）记录证据。

## 8. 已知、不在本版范围的问题

遇到这些照实记录，标「已知」，不作为本版失败：

- 托管音频、托管超分没有开启。开启前还有两处缺陷要修：托管超分会丢掉原视频的声音；托管音频收不到操作类型和歌词参数。
- 用户手动取消、但已经提交到上游的视频任务，后台仍显示「可以取回」，但取回接口拒绝已取消的任务。产品上还没定取消后能不能取回。
- GitHub 上仍开着的 #213（Ubuntu 22.04 @ 素材后黑屏）、#210（三个视频插件字段与官方不一致）、#181（Agnes 插件默认拦截本地参考图）、#148（中文界面下助手字节编码错误）、#112（技能正文超过 64KB），本版没有改动。
