# 画布失败信息的保存与旧节点回填

本候选保留既有错误归类规则及旧节点推断。冻结行为测试除首次读取外，也检查保存、重新打开后的提示与操作。

`canvas-node-failure-view.ts` 是节点失败的读取入口，只计算调用方实际读取的字段。错误卡片、悬停工具、批次筛选、恢复和审核重置继续使用原判断；“去生成历史”按实际显示的 `result_target_unavailable` 类别决定。

节点编辑由 `useCanvasNodeState` 统一保存现有归类结果、规范化提示及其输入标识。外部加载和刷新先原样接收文档，首次后台读取结束后才保存旧失败信息，避免把恢复时的临时状态误当用户修改。上传中断和正在恢复的提示不作为生成失败保存。读取时输入未变就复用 `generationFailure`；错误、任务号、模型、时间或影响提示的阶段变化时，写入端重新保存。成功或下一次提交会清除旧记录。浏览器渠道的已归类异常也保留第一次归类，避免把规范化中文当供应商原始错误再判断。

没有任务号的失败按现有 `readNodeTaskOutcome` 规则保存一次 `taskOutcome`，标为 `taskOutcomeSource: local`。这只是本地操作结论，不证明上游接收、成功、扣费或退款。后补“提交未确认”等标记时仍重新计算；后台返回的结论具有优先权，不被本地失败覆盖。

打开有任务号、缺少结论的旧节点时，仍需恢复的节点继续由既有恢复流程读取；其余稳定节点由 `canvas-task-outcome-backfill.ts` 最多同时读取四个原任务，只保存实际返回的 `outcome`，避免同一节点重复查询。查询失败、404 或没有结论时保留旧推断，不创建或恢复任务。写入前核对画布、账号、节点、任务号和操作绑定；晚到的结果不覆盖新的绑定或结论。

旧推断在回填后至少保留两个发版周期，再依据届时的覆盖证据单独删除。本候选没有删除推断，也不把本地回填等同于后台持久任务。
